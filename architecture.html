Factory Inventory Management System

A demo dashboard. A Vue 3 single-page app reads from a FastAPI service that serves in-memory data loaded from JSON files. There is no database.

System architecture

Two processes run locally. The browser talks to Vite on port 3000, and the app calls the API directly on port 8001.

Data flow

A filter change triggers one request per view. All four filters travel as query parameters.

  1. User changes a filterFilterBar writes to shared refs in useFilters (period, location, category, status).
  2. View reads the filtersgetCurrentFilters() maps them to warehouse, category, status, and month.
  3. api.js builds the requestValues equal to all are dropped. axios sends a GET to localhost:8001/api/....
  4. FastAPI filters in memoryapply_filters and filter_by_month run over the lists loaded at startup. Months accept 2025-03 or Q1-2025.
  5. Pydantic validates the responseThe handler returns data shaped by its response_model, serialized as JSON.
  6. View rendersRaw data lands in refs. Computed properties derive totals and chart series, which drive the SVG and tables.

GET /api/orderswarehouse, category, status, month

GET /api/demandnone
GET /api/backlognone (adds has_purchase_order)
GET /api/spending/*none (summary, monthly, categories, transactions)
GET /api/reports/*none (quarterly, monthly-trends, computed from orders)
GET /api/inventory/{id}, /api/orders/{id}lookup by id, 404 if missing

Inventory has no time dimension, so it ignores the period filter.

Gaps found while reading the code

  • api.js defines calls to /api/tasks and /api/purchase-orders, but server/main.py has no matching routes. Those requests would return 404 today. The backend defines Pydantic models for purchase orders and loads purchase_orders.json, so the routes look unfinished.
  • Backlog.vue exists in views/ but is not registered in the router.
  • The API base URL is hard-coded to http://localhost:8001/api in api.js.
  • CORS allows all origins and there is no authentication. This is fine for a local demo only.
  • Data resets on every server restart because nothing is written back to disk.
